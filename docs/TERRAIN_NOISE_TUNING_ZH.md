# 点云噪声与局部凸起：地形分析调参指引

## 1. 适用范围与基本原则

本指引用于排查点云噪声引起的局部地面估计异常、虚假凸起和路径误阻塞，重点针对基础节点 `terrainAnalysis`。参数作用总览见[项目指南第 7.2 节](./PROJECT_GUIDE_ZH.md#72-地形分析)。

**先判断是地面基准错误，还是正常地面上存在噪声点，再选择调参方向。降低分位数、增大体素或放宽规划阈值不能互相替代，也不能保证消除所有噪声。**

当前[地形启动配置](../src/terrain_analysis/launch/terrain_analysis.launch)中的相关值为：

| 参数 | 配置值 | 含义 |
| --- | --- | --- |
| `useSorting` | `true` | 使用高度分位数估计地面 |
| `quantileZ` | `0.35` | 使用排序后约 35% 位置的高度 |
| `limitGroundLift` | `false` | 不限制地面估计相对最低点的抬升 |
| `maxGroundLift` | `0.15 m` | 仅在开启抬升限制时生效 |
| `scanVoxelSize` | `0.05 m` | 点云体素下采样尺寸 |
| `minBlockPointNum` | `10` | 平面格所需支持点数 |
| `considerDrop` | `true` | 使用点与地面估计的绝对高差 |

这些是编写本指引时的 launch 配置，不是所有场景通用的推荐值，也不一定等于节点当前运行值。试验前检查 `rqt_reconfigure` 中的实际设置；在线可调参数以 [TerrainAnalysis.cfg](../src/terrain_analysis/cfg/TerrainAnalysis.cfg) 为准。

## 2. 先识别问题类型

在 RViz 中对照 `/registered_scan` 和 `/terrain_map`，固定坐标系为 `map`，将地形图按 **Intensity** 着色，并固定色标范围，避免自动缩放颜色造成误判。

`/terrain_map` 不是被压平的地面模型：输出点保留地图坐标 `xyz`，`intensity` 才是相对地面高差。几何上看到凸起，不一定说明估计的地面基准被抬高；节点也没有单独发布内部的地面高度网格。

| 类型 | 观察线索 | 优先处理 |
| --- | --- | --- |
| 地面基准偏高 | 正常低处地面也出现较大绝对高差，局部高点反而代价偏低 | 降低 `quantileZ`，必要时验证抬升限制 |
| 地面基准正常、存在向上噪声 | 大部分地面代价接近零，仅少量高点代价明显偏大 | 小幅调整下采样，必要时增加上游离群点过滤 |
| 向下噪声拉低地面基准 | 低点附近一片正常地面都出现正高差 | 不要继续降低分位数；检查低点噪声，保持抬升限制关闭做对照 |
| 输入配准或裁剪异常 | 平地出现重影、层叠，或地面点在部分区域消失 | 先检查时间戳、位姿、坐标系及高度裁剪范围 |
| 感知基本正常但路径过于敏感 | 少量高代价点使候选路径被阻塞 | 最后再校准规划器阈值，不将其当作感知修复 |

上述现象仅是诊断线索，应结合原始点云和现场已知平地确认。如果局部只观测到物体顶部、没有真实地面样本，单纯改变分位数也无法恢复缺失的地面。

## 3. 地面基准被高点抬高

保持其他参数不变，先将 `quantileZ` 从 `0.35` 调为 `0.25`，对比同一段数据；确认方向有效后，才考虑试 `0.15`。

- 降低分位数可减少高处点对地面高度估计的影响。
- 分位数越低，越容易受向下离群点、坑洞和坡面低侧样本影响。
- 不建议直接关闭 `useSorting`：关闭后使用最低点，可能进一步放大向下噪声的影响。

如果分位数调整仍无法避免地面基准被抬高，且已确认最低点可靠，再单独开启 `limitGroundLift`。先保留 `maxGroundLift=0.15 m`，之后按需要试 `0.10 m`，不要同时改动多个参数。

排序模式下，[实际计算逻辑](../src/terrain_analysis/src/terrainAnalysis.cpp)相当于：

```text
limitGroundLift = false:
  ground_z = quantile_height

limitGroundLift = true:
  ground_z = min(quantile_height, minimum_height + maxGroundLift)
```

这里的最低点来自当前平面格及邻域提供的高度样本。**这不是跨帧平滑，也不是直接削平输出凸起。** 如果最低点是向下噪声，开启限制可能压低地面基准，让正常地面或真实台阶显得更高。

## 4. 地面正常，但存在向上噪声点

不要以持续降低 `quantileZ` 为主要手段。地面基准降低后，高处噪声点相对地面的高差可能反而增大。

### 4.1 小幅调整下采样

将 `scanVoxelSize` 从 `0.05 m` 逐步试为 `0.075 m`，必要时再试 `0.10 m`。修改该启动参数后需重启节点。

- 同一体素内多个点合并，可能减弱密集的小尺度抖动。
- 独立体素中的孤立噪声不会因此自动消失；位于不同高度体素的点也不一定被合并。
- 体素过大会损失细杆、台阶边缘和真实小障碍，不能只以“地图更平整”为成功标准。
- `scanVoxelSize` 不改变源码中的 `0.2 m` 地面估计平面格尺寸。
- 当前下采样仅在体素更新条件满足时执行，不能假定每个体素每帧都会经过滤波。

### 4.2 不要用支持点数阈值替代离群点滤波

`minBlockPointNum` 检查平面格的支持样本数，样本包含邻域共享的点，并不是检查某个凸起点是否孤立。

密集平地上的孤立高点所在格仍可能有充分支持，提高该值未必有效；在稀疏区域提高阈值却可能造成地形图缺失。尤其在 `noDataObstacle=false` 时，缺图不等于安全地删除噪声。

### 4.3 何时需要上游滤波

若持续存在独立的异常高点或低点，可考虑在地形分析之前增加半径离群点过滤或统计离群点过滤。当前节点没有可直接开启这类过滤的参数，需要另行实现或接入预处理节点。

滤波强度应按传感器距离、点密度和最小必检障碍尺寸校准；远处稀疏表面、细杆和小障碍不能被当成噪声一起删除。输出仍需保持 `/registered_scan` 所要求的坐标系、时间戳和字段契约。

## 5. 最后再调整规划器容忍度

当前[局部规划配置](../src/local_planner/launch/local_planner.launch)中，`obstacleHeightThre=0.15 m`、`pointPerPathThre=2`、`useCost=false`。

- `obstacleHeightThre`：地形点高差超过该值才作为硬障碍。提高它会同时忽略一部分真实小障碍。
- `pointPerPathThre`：候选路径的障碍命中计数阈值。提高它可能减少孤立点误阻塞，但也可能放过点数较少的真实障碍；它不是原始点云中的物体点数。
- `groundHeightThre`、`costHeightThre` 等软代价参数不能替代硬障碍阈值；当前 `useCost=false`，不应依赖调整软代价参数解决问题。

只有确认噪声高差明显低于底盘必须避让的最小障碍高度后，才考虑小幅调整规划阈值。若噪声与真实障碍高度重叠，仅靠高度阈值不能可靠区分，应优先改善感知。

不要通过降低 `vehicleHeight`、缩窄高度裁剪范围来隐藏高代价点；这些操作也会删除真实障碍。不要通过加强 `clearDyObs` 清除静态噪声，也不要为了消除视觉异常直接关闭 `considerDrop`，否则可能失去对真实落差的风险表达。

## 6. 当前实现的时间记忆限制

[基础节点主循环](../src/terrain_analysis/src/terrainAnalysis.cpp)每次处理新点云时都会重新创建全部滚动体素点云，上一帧的观测因此被丢弃。当前不能依赖调整 `decayTime`、`noDecayDis` 获得正常的跨帧平滑或历史点衰减效果。

`voxelPointUpdateThre` 和 `voxelTimeUpdateThre` 影响下采样及筛选触发时机，不是时间平均参数。若需要跨帧稳定地面估计，应单独修正并验证地图生命周期或实现时间滤波，不能仅靠改 launch 数值。本指引不修改算法行为；此限制也不应直接套用于扩展节点 `terrainAnalysisExt`。

## 7. 建议试验顺序与验收

1. **保存基线**：固定场景、传感器设置及速度，先在机器人静止或禁止运动时采集数据；检查配准和高度裁剪。记录运行参数、输入点云、里程计及地形/规划输出，便于复现。
2. **分类**：对照已知平地，确认是地面基准偏高、偏低，还是只有孤立噪声点。不要只看 RViz 中的几何凸起。
3. **单变量试验**：基准偏高先试 `quantileZ=0.25`；若仅高处孤立噪声，则保留地面估计配置，优先试小幅下采样。无改善时回退，不盲目叠加参数调整。
4. **必要时升级处理**：最低点可靠时再试抬升限制；孤立离群点持续存在时评估上游滤波。感知稳定后才校准规划阈值。
5. **带真实障碍复核**：同时测试平地、坡面、最小必检小障碍、细杆及安全条件下的落差场景。低速验证必须具备急停条件，不用真实行驶来试探未知危险。
6. **持久化**：`quantileZ`、`limitGroundLift`、`maxGroundLift` 可通过 `rqt_reconfigure` 试调；`scanVoxelSize` 需修改 launch 后重启。有效的在线调整最终写回对应 launch，并在重启后复核实际值。

建议记录以下结果，而不只记录“看起来更平整”：

| 项目 | 验证内容 |
| --- | --- |
| 平地误报 | 相同距离范围内，高代价点数量及误阻塞路径次数是否下降 |
| 地面覆盖 | 是否新增空洞，尤其是远处和遮挡边缘 |
| 真实障碍 | 最小必检障碍、细杆和台阶是否仍产生足够高差并阻塞路径 |
| 落差表达 | 改动是否导致真实落差失去风险代价 |
| 稳定性与性能 | 地形图频率、延迟、CPU 开销及重复试验结果是否可接受 |

验收标准应先由底盘通行能力、传感器精度和任务安全要求确定。若只减少误报却增加真实障碍漏检，应回退该次调整。
